/ Executive Summary

An extensive interactive runtime audit and static code profiling session was conducted on the Shiva Portfolio web application. While the website features advanced visual design, smooth animations, and interactive 3D sculptures, several architectural patterns produce severe micro-stutter, heavy main-thread CPU bottlenecks, and GPU fill-rate exhaustion across desktop and mobile browsers.

The primary performance degradations stem from unthrottled React state dispatches inside mouse tracking listeners, simultaneous GSAP pinning inside CSS sticky stacked cards, high-resolution canvas rasterization, and heavy multi-pass post-processing.

/ Deep-Dive Technical Root Cause Analysis

Critical #1 Mouse-Move Layout Reflow & React State Thrashing
src/components/ui/Resume3DCard.jsx:146-165

The 3D card tilt physics calculation listens to raw onMouseMove events without debounce or requestAnimationFrame throttling. Inside the listener:

const handleMouseMove = (e) => { const rect = cardRef.current.getBoundingClientRect(); // 🚨 FORCED SYNCHRONOUS LAYOUT REFLOW setCardTransform(`perspective(2000px) rotateX(${rotateX}deg) ...`); // 🚨 Full Component Re-render setGlarePos({ x: glareX, y: glareY, opacity: 0.25 }); // 🚨 Second State Re-render };
  • Layout Thrashing: High-polling mice emit 120Hz–1000Hz pointer events. Calling getBoundingClientRect() forces Chromium to flush pending layout changes and synchronously compute geometry 100+ times per second.
  • React Re-render Flood: Triggering two setState calls per mouse pixel triggers massive virtual DOM diffing while the user is simply hovering over the card.
  • Excessive Texture Memory: Lines 117-124 render the PDF page at scale = 3.0 onto a 2D canvas (~1785 × 2526 px), requiring over 18 MB of GPU texture memory.
Remediation: Mutate CSS transform directly on the DOM element inside an RAF loop (cardRef.current.style.transform = ...), completely bypassing React state re-renders. Downscale PDF render scale to 1.5.
High #2 Scroll Architecture Conflict: GSAP Pinning inside CSS Sticky Stacking
src/components/sections/Experience.jsx & StackScroller.jsx

StackScroller.jsx wraps each portfolio section in a position: sticky; min-height: 100vh container (.card__conceal). Concurrently, Experience.jsx instantiates two independent TimelineCarousel components with:

ScrollTrigger.create({ trigger: sectionRef.current, start: 'center center', end: () => `+=${items.length * 650}`, pin: true, // 🚨 GSAP wraps target in pin-spacer with position: fixed scrub: 0.5, });
  • Sticky vs Fixed Contention: GSAP's pinning mechanism creates a synthetic spacer element and toggles position: fixed relative to the viewport. When nested inside an active CSS position: sticky hierarchy, the browser's scroll compositor encounters conflicting stacking contexts, resulting in severe jitter, sudden jumps, and scroll-lock fighting with Lenis.
  • 500vh Compositing Overlays: In StackScroller.css, .overlay__conceal::before is styled with height: 500vh; will-change: opacity;. This allocates enormous empty black compositing textures across multiple stacked cards, causing memory strain on mobile devices.
Remediation: Remove pin: true from TimelineCarousel. Rely on native horizontal Embla touch/wheel swipe or non-pinned scrub animations. Replace height: 500vh with inset: 0.
High #3 Hero 3D Canvas Continuous Loop & Hyperspeed Post-Processing Freeze
src/components/sections/Hero.jsx & Hyperspeed.jsx
  • Continuous GPU Execution: <Canvas frameloop="always" shadows ...> renders continuously even when the user is idle. It renders directional shadow maps (512x512) and ACESFilmic tone-mapped HDR reflections 60–120 times every second.
  • Shader Compilation Hitch on Toggle: Clicking the bottom-right shutter toggle dynamically unmounts the 3D model and mounts Hyperspeed.jsx. This forces the browser to dynamically allocate a new WebGL context, compile complex noise distortion GLSL shaders, and build an EffectComposer with BloomEffect and SMAAEffect on the main thread, resulting in a visible 300ms freeze.
Remediation: Switch Three.js Canvas to frameloop="demand" and call invalidate() only during mouse motion. Pre-warm or simplify Hyperspeed shaders, eliminating multi-pass Bloom/SMAA on mobile.

/ Secondary Findings & Asset Analysis

Medium #4 Kinetic Typography Animation Frame & Remote Asset Roundtrips
src/components/ui/ScrollVelocity.jsx & Skills.jsx
  • Unthrottled useAnimationFrame: ScrollVelocity.jsx runs a continuous animation frame loop updating Framer Motion baseX transform offsets across 24 DOM <span> elements even when the window is not scrolling.
  • Competing Layout Engines: The orbit ring in Skills.jsx applies GSAP scrubbed rotation to .orbitRotatingWrapper while simultaneously managing 25+ motion.div nodes with Framer Motion spring physics (layoutId), causing layout thrashing when changing active skills.
  • Unbundled SVG Downloads: skills.json points to over 25 individual external vector logos on https://svgl.app/library/..., generating 25+ remote HTTP requests on runtime instead of being compiled into the local build bundle.
